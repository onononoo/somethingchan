overview

somethingchan is 19 pages of html and css. there is no build step, no framework and no javascript. interactivity comes from a small set of techniques that browsers already support. each one is documented below with the code and a working demo on this page.

rule #1

no javascript, anywhere. this is enforced two ways: nothing on the site is written in javascript, and every page sends script-src 'none' so the browser would refuse to run it anyway.

techniques

content-security-policy

every page ships a meta tag that forbids scripts. even if a script tag sneaks in, the browser refuses to run it. this is rule #1, enforced by the browser instead of by discipline.

<meta http-equiv="content-security-policy"
      content="script-src 'none'; object-src 'none'">
/* nothing. the browser does the work. */
live demo

this page has the tag. there is nothing to click: the demo is that nothing runs.

used on: every page

checkbox state

a hidden checkbox stores on/off. a label toggles it. css reads it with :checked, or with :has() from anywhere above it.

<input type="checkbox" id="lamp" hidden>
<label for="lamp">toggle</label>
<div class="bulb"></div>
.bulb { background: #ccc; }
body:has(#lamp:checked) .bulb { background: #555; }
live demo

used on: theme toggle, dungeon inventory, recycle bin, pledge

radio groups

radios with the same name are mutually exclusive, which makes them a tab switcher, a filter, or a view mode.

<input type="radio" name="t" id="a" checked>
<input type="radio" name="t" id="b">
<label for="a">a</label> <label for="b">b</label>
.pa, .pb { display: none; }
:has(#a:checked) .pa,
:has(#b:checked) .pb { display: block; }

this is panel b.

used on: species tabs, /qa/ themes, catalog, gallery filter, soytionary

:target routing

a link to #something makes that element the :target. show only the targeted section and you have pages without a router.

<a href="#p2">go to page 2</a>
<section id="p1">…</section>
<section id="p2">…</section>
section { display: none; }
section:target { display: block; }
live demo

used for every room in the dungeon and every tab on the wiki. this docs page uses it too: the sidebar links jump here.

used on: dungeon rooms, wiki tabs, footnotes

:has() as logic

:has() lets a parent react to anything inside it. chain several and you get and; put a list inside and you get or. that is enough for win detection.

<div class="game">
  <input type="checkbox" id="c1">
  <input type="checkbox" id="c2">
</div>
.game:has(#c1:checked):has(#c2:checked) .msg::after {
  content: "both checked";
}
live demo

used on: gem-tac-toe, minesweeper, merge puzzle, quiz

css counters

counter-increment on checked inputs, counter() in generated content. the counter only sees elements that come earlier in the page, so put the readout after the inputs.

<input type="checkbox" class="v">…
<p class="score"></p>
.box { counter-reset: n; }
.v:checked { counter-increment: n; }
.score::after { content: counter(n); }
live demo

used on: tallies, vote counts, minesweeper, whack-a-js

@property counters over time

register a custom property as an <integer>, animate it, and feed it to a counter. that is a number that counts up with no script.

<b class="tick"></b>
@property --n { syntax: "<integer>"; inherits: false; initial-value: 0; }
.tick { animation: up 20s linear forwards; counter-reset: n var(--n); }
.tick::after { content: counter(n); }
@keyframes up { to { --n: 200; } }
live demo

used on: shame counters, uptime clock, ddos map, npm install

popover

the popover attribute plus a button with popovertarget gives you dialogs, menus and windows. popover="manual" lets several stay open.

<button popovertarget="w">open</button>
<div id="w" popover>hello</div>
[popover] { padding: 1em; }
live demo
this is a popover.

used on: somethingos, kara lightbox, merge conflict dialog

details name=

details elements that share a name attribute form an exclusive accordion. opening one closes the others.

<details name="faq"><summary>a</summary>…</details>
<details name="faq"><summary>b</summary>…</details>
/* none needed */

form reset

a button with type="reset" restores every input in its form. that is a "new game" button that html has had since the 90s.

<form>
  <input type="checkbox">
  <button type="reset">new game</button>
</form>
/* none */
live demo

used on: arcade, minesweeper

@media (scripting)

the scripting media feature tells css whether the browser would run javascript. a style inside <noscript> is a second signal. neither needs a script.

<noscript><style>.on { display: none; }</style></noscript>
@media (scripting: none) { .on { display: none; } }
live demo

used on: /js/

stacked links on a timer

put several links in the same spot and make each visible for a slice of a fast animation. the click lands on whichever one is showing. that is a random link.

<span class="r">
  <a href="#a">random</a>
  <a href="#b">random</a>
</span>
.r a { animation: s .4s steps(1) infinite; }
.r a + a { position: absolute; animation-delay: -.2s; }
@keyframes s { 50% { visibility: hidden; } }
live demo

see "random article" on the wiki.

used on: wiki random article
